# モデル操作の改善 設計

日付: 2026-08-08
対象ブランチ: feat/self-model-placement-remaining
前提: `2026-08-08-model-operation-window-design.md`（モデル操作ウィンドウ本体の設計）

## 背景

モデル操作ウィンドウを導入したあと、実際に使って以下 3 点の不具合・不足が判明した。

1. モデルを配置すると 3D 上にギズモが出て「選択されている」ように見えるが、操作ウィンドウのモデル一覧では未選択のまま。選択状態が 3D 上のどこにも表れていない
2. モデル操作ウィンドウは編集モードが「モデル」の間つねに表示され、ユーザーが閉じられない
3. Transform 行の X/Y/Z ラベルを左右ドラッグして数値を変えている最中、カーソルが 3D 上のギズモ領域に入るとギズモに操作を奪われ、モデルが意図せず動く

あわせて、ギズモが編集モードに関係なく出っぱなしになっている点と、ギズモを消す手段がない点も解消する。

## 要件

- 配置直後のモデルが操作ウィンドウでも選択状態になること
- 選択中モデルが 3D 上でも判別できること
- ギズモは全モデルに出したままとし、表示はモデル編集モード中に限ること
- ギズモの操作種別ラジオに「なし」を追加し、ギズモを消せること
- モデル配置行の「配置」ボタンの横に「操作」ボタンを置き、押下で操作ウィンドウの表示/非表示を切り替えられること
- ドラッグラベル操作中にギズモへ操作が奪われないこと

## 1. 選択状態と配置時の自動選択

### 現状

- 選択状態は `ModelOperationWindow._selectedModel` が保持し、モデル一覧のクリックでのみ設定される
- `ModItemManager.CreateModel` → `ModelPlacerManager.CreateModel` は戻り値 void で、生成された `StudioModelStatWrapper` が UI に渡らない
- 選択状態は一覧の文字色（緑）にしか表れず、3D 上では区別できない

### 変更

選択状態の持ち主を `SelfModelPlacer` へ移す。配置直後の自動選択と、選択に連動したマテリアル制御（後述）を placer 側で完結させるため。

- `SelfModelPlacer.selectedModel` を新設する
  - getter: 保持中の wrapper の `obj as GameObject` が破棄済み（null）なら `null` に戻す（`ModelOperationWindow` の既存 getter をそのまま移植）
  - setter: 値が変わったとき、旧選択のハイライトを解除し、新選択のハイライトを開始する
- `CreateModel` は成功時の最後に `selectedModel = wrapper` を設定する。これで配置直後は一覧でも選択中になる
- `DeleteModel` は削除対象が選択中なら選択を解除する。`DeleteAll` は選択を `null` にする
- `LoadPreset` は内部で `CreateModel` を繰り返すため最後のモデルが選択された状態になる。復元完了後に `selectedModel = null` にする
- `ModelOperationWindow.selectedModel` は `placer.selectedModel` への委譲プロパティにする。ウィンドウ内の既存の参照箇所（一覧の色分け・クリック、Transform 行、削除、プリセット読込後の null 代入、`OnChangedSceneLevel`）は変更不要

`ModItemManager.CreateModel` および `ModelPlacerManager.CreateModel` のシグネチャは変更しない。生成物を UI まで引き回す必要がなくなるため。

## 2. 選択中モデルのハイライト（`_Color` フェード）

### 手法の選定

実機（COM3D2.5 稼働中）で配置済みモデルのマテリアルを確認したところ、シェーダは `CM3D2/Lighted` および `CM3D2/Lighted_Trans` で、`_OutlineColor` / `_OutlineWidth` を**持たない**。アウトライン付きは `Toony_Lighted_Outline` 系（主に衣装）で、家具・小物系のモデルでは使えない。一方 `_Color` はどちらのシェーダにも存在する。

そこで選択中モデルのマテリアル `_Color` を周期的にフェードさせて示す。

### 変更

- ハイライト対象は選択モデル配下の全 `Renderer` の `sharedMaterials` のうち `_Color` を持つもの。`ImportCM.LoadMaterial` はモデルごとに新しい `Material` を生成するため、他モデルへ波及しない
- 選択が変わった時点で、対象マテリアルと元の `_Color` の対を記録する。解除時はこの記録から厳密に書き戻す
- ハイライトはモデル編集モード中に限る（第 3 節の編集モードフラグを共有する）。モードを抜けても選択自体は保持し、色だけ元に戻す。ギズモは編集モード外で隠すのにハイライトだけ明滅し続けるのは不自然なため
- `SelfModelPlacer.Update()` でハイライト色を毎フレーム更新する。元色と強調色をサイン波（`Mathf.Sin`）で往復補間する。周期と強度は定数として定義する
  - アルファは元の値を保持する。`Lighted_Trans` で透明度が揺れるのを避けるため
- 解除（`_Color` を元に戻す）を行うのは次のすべて: 選択解除・別モデルの選択・選択モデルの削除・`DeleteAll`・シーン遷移・プラグイン無効化。モデル破棄が先行してマテリアルが `null` になっている場合は書き戻しをスキップする
- 非表示（`visible == false`）モデルはレンダリングされないためハイライトは見えない。マテリアルの記録・書き戻しは通常どおり行う

## 3. ギズモの表示条件と「なし」の追加

### 変更

- `SelfModelPlacer.GizmoDragType` に `None` を追加し、`ModelOperationWindow.DrawGizmoRow` のラジオへ「なし」を先頭に追加する
- あわせて同行の `(全モデル共通)` ラベルは削除する
- `SelfModelPlacer` に編集モードフラグを設け、`ModelOperationWindow.Update()` が毎フレーム「編集モードがモデルか」を代入する。ウィンドウの開閉状態（第 4 節の `_userVisible`）とは独立させる。ウィンドウを閉じてもギズモは操作できるべきなので。このフラグは第 2 節のハイライトの有効条件も兼ねる
- 各ギズモの可視は `Visible = (編集モードフラグ && dragType != None)` とする。`GizmoRender.OnRenderObject` は `Visible == false` で即 return するため、これだけで描画も操作も止まる
- `AddGizmo` は生成時に上記と同じ条件を適用する。編集モード外で配置した場合にギズモが出ないようにするため

ギズモは従来どおり全配置モデルに出る。選択状態との連動はしない（選択は第 2 節のハイライトで示す）。MTE 側に配置したモデル（`pluginName != ModItemExplorer`）はこれらの制御の対象外で、ギズモは MTE の管轄のまま。

## 4. 「操作」ボタンによるウィンドウ表示トグル

### 現状

`ModelOperationWindow.Update()` が毎フレーム `isShowWnd = (modItemWindow != null && modItemWindow.isModelMode)` を代入するため、ユーザー操作で閉じても次フレームに再表示される。

### 変更

- `ModelOperationWindow` にセッション内のみ保持するフィールド `_userVisible`（初期値 `true`）と、それを反転する公開メソッドを追加する。設定ファイル（`Config`）には保存しない
- `Update()` の表示判定を `isShowWnd = isModelMode && _userVisible` に変更する。プリセット一覧の再読込フラグ（非表示→表示への遷移で `_presetNamesDirty = true`）のロジックはそのまま流用する
- `Close()` は `isShowWnd = false` に加えて `_userVisible = false` も落とす。落とさないと次フレームの `Update()` で再表示されてしまう。`Close()` はプラグイン無効化時にも呼ばれるため、無効化→再有効化するとウィンドウは閉じた状態から始まる（「操作」ボタンで開き直せるため許容する）
- `ModItemWindow.DrawModelPlacementRow` の「配置」ボタンの右に `view.DrawButton("操作", 50, 20)` を追加し、押下で上記の反転メソッドを呼ぶ。開閉状態はボタンの見た目には反映しない

「配置」ボタンはプラグイン未選択時に描画されないが、「操作」ボタンはプラグイン選択の有無に関わらず常に描画する。ウィンドウの開閉は配置プラグインの選択と無関係のため。

## 5. IMGUI ドラッグ中のギズモ入力抑止

### 原因

`GizmoRender.Update()` は `NInput` を直接読み、マウス押下フレームに `UICamera.Raycast`（NGUI のヒット判定）だけを見て `is_drag_` を決める。IMGUI（`GUI.Window`）は NGUI ではないため、プラグインのウィンドウ上で押下しても `is_drag_ = true` になる。その後 `OnRenderObject()` 内でカーソルがハンドル上に来た時点で `beSelectedType` が確定し、ドラッグが横取りされる。

`GizmoRender.global_control_lock`（`control_lock` プロパティ経由）は `beSelectedType == MOVETYPE.NONE` からの**新規ハンドル選択**を止めるフラグなので、これを立てておけば横取りを防げる。すでに選択済みのギズモ操作は止まらないが、IMGUI ドラッグは押下時点でギズモ未選択なので問題にならない。

### 変更

抑止の実装場所は `WindowManager.UpdateInputBlock`。ここには既にカメラ操作（`MainCamera.SetControl`）と NGUI 入力（`UICamera.InputEnable`）に対する同種の遮断があり、「ゲーム側入力をウィンドウ操作中だけ止める」という関心事が揃っている。

- `UpdateInputBlock` から `UpdateGizmoLock(GUIUtility.hotControl != 0)` を呼ぶ
- `UpdateGizmoLock` は既存の `UpdateUIInput` と同じガードを踏襲する。すなわち自分が有効化した記録（`_isGizmoLocked`）を持ち、自分が立てたときだけ倒す。ゲーム本体や他プラグインが立てた `global_control_lock` を誤って解除しないため
- `RestoreInputBlock`（プラグイン無効化・シーン遷移時）にもロック解除を追加する

条件は `GUIUtility.hotControl != 0`、つまり IMGUI の何らかのコントロールがマウスを掴んでいる間すべて。ドラッグラベルに限らず、数値フィールドの選択ドラッグやウィンドウ移動中も対象になる。ドラッグラベル専用のフラグを MTEUtils サブモジュール側に追加する案と比べ、サブモジュールを変更せずに済み、同種の横取りを一律に防げる。

### 既知の制約

`GizmoRender.global_control_lock` は `GizmoRender` の `public static` フィールドで、派生クラス（MTE が使う `GizmoRenderTarget` 等）を含むシーン内の全ギズモに効く。`GUIUtility.hotControl` はこのプラグインのウィンドウに限らず立つため、他ウィンドウ・他プラグインの IMGUI ドラッグ中も一時的に MTE 側ギズモの新規ハンドル選択が止まる。ロックの対象は新規選択だけで、進行中のドラッグは止まらず、マウスを離せば即解除されるため実害は一過性と判断して許容する。

`isMouseOverWindow` との AND でスコープを絞る案は採らない。ドラッグ中にカーソルがウィンドウ外（＝ギズモ上）へ出た瞬間にロックが外れ、防ごうとしている横取りがそのまま再発するため。

`GUIUtility.hotControl` は `OnGUI` で立ち、`WindowManager.Update` で読むため 1 フレームの遅延がある。実害が出るのは「押下した瞬間からラベルがギズモハンドルに重なっていた」場合のみで、報告された「ドラッグ開始後にギズモ領域へ侵入する」ケースはロック済みのため防げる。この 1 フレームのすり抜けは許容する。

## テスト

自動テストの仕組みを持たないプラグインのため、実機（COM3D2.5 起動状態）での手動確認とする。

1. モデルを配置 → 操作ウィンドウの一覧で緑表示（選択中）になり、3D 上でそのモデルの色が周期的にフェードすること
2. 2 体目を配置 → ハイライトが 2 体目へ移り、1 体目の色が元に戻ること
3. 一覧で 1 体目をクリック → ハイライトが 1 体目に戻ること。ギズモは両方に出たままであること
4. 選択中モデルを削除 → 選択が解除されること。残ったモデルの色が変化していないこと
5. プリセット読込 → 選択なしの状態で復元され、どのモデルもハイライトされていないこと
6. 編集モードをモデル以外へ切替 → ギズモが消え、ハイライトの明滅も止まって元の色に戻ること。モデルへ戻すと両方とも再開し、選択も保たれていること
7. ギズモのラジオで「なし」を選択 → 全モデルのギズモが消え、3D 上でドラッグしてもモデルが動かないこと。移動/回転/拡縮へ戻すと復帰すること
8. 「操作」ボタン押下 → ウィンドウが閉じる。再押下で開く。閉じている間もギズモ操作・回転オイラー角の正規化が従来どおり働くこと
9. 編集モードをモデル以外へ切替 → ウィンドウが隠れ、モデルへ戻すと直前の開閉状態が保たれること
10. 位置 X ラベルをギズモ領域を横切るように長くドラッグ → 数値だけが変わり、ギズモに掴まれないこと
11. ドラッグを離したあと 3D 上のギズモを直接操作 → 従来どおり動くこと（ロックが正しく解除されている）
12. シーン遷移・プラグイン無効化 → マテリアルの色が元に戻ること（ハイライト解除漏れがないこと）
